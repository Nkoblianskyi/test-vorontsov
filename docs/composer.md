# Composer — наше видение сервиса

Маршрут: `/vision` (новый счёт) и `/vision/[id]`. Пункт **Vision ✦** в навигации. Код: `src/views/composer/`.

## Зачем отдельный экран

В классической схеме (и в референсе) счёт делается в двух местах: форма генератора и отдельный редактор шаблона. Бухгалтер переключается между экранами, сохраняет, возвращается и проверяет результат.

Composer собирает это в одно место: **лист и есть редактор**. Всё остальное — форма, дизайн, навигация, действия — на расстоянии одного клика или одной клавиши.

## Экран

```
┌ Composer ─ INV-0007 · Saved 14:02 ────────── [Search or run a command ⌘K]  Print  [Mark as sent] ┐
├──────────────┬───────────────────────────────────────────────┬──────────────────────────────────┤
│ + New invoice│                                               │  Invoice │ Design                │
│ [filter]     │            A4-лист, редактируемый              │  01 Customer                     │
│ INV-0007  ●  │            прямо на месте                      │  02 Details                      │
│ INV-0006  ●  │                                               │  03 Line items …                 │
│ …            │                                               │  или: Look / Wording шаблона     │
└──────────────┴───────────────────────────────────────────────┴──────────────────────────────────┘
```

- **Слева** — все счета: фильтр, статус, остаток. Переход без выхода из экрана.
- **В центре** — лист A4 с масштабом.
- **Справа** — инспектор:
  - **Invoice** — те же секции, что в генераторе;
  - **Design** — настройки Studio для шаблона этого счёта.

## Ключевые решения

| Решение                         | Как работает                                                                                                                                                                                                                                      |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Правка прямо на листе**       | Клик по тексту открывает поле ввода точно поверх него: тем же шрифтом, размером и цветом, в масштабе листа. **Tab** — следующее поле, **Shift+Tab** — предыдущее, **Enter** — готово, **Esc** — вернуть как было.                                 |
| **Всё остальное — в один клик** | Даты открывают календарь в инспекторе. Логотип, подписи колонок и платёжный блок открывают нужную настройку во вкладке Design. Заголовок документа правится на месте, хотя принадлежит шаблону.                                                   |
| **Нет кнопки Save**             | Счёт и шаблон сохраняются сами через 0.7 с после паузы. В шапке статус: «Saving…», «Saved 14:02» или «Not saved · Who is this invoice for?». Новый счёт сохраняется, как только становится валидным; адрес страницы обновляется без перезагрузки. |
| **⌘K / Ctrl+K**                 | Одна строка для всего: новый счёт, «Mark as sent / paid», добавить строку, клиент, печать, дублировать, удалить, сменить шаблон, применить пресет, перейти к любому счёту. Поиск по нескольким словам в любом порядке.                            |
| **Дизайн — в контексте счёта**  | Вкладка Design правит шаблон этого счёта и честно говорит, если он общий: «Shared by 5 invoices». Кнопка **Make a copy for this invoice** делает копию для клиента и переключает на неё счёт.                                                     |
| **Одна следующая кнопка**       | В шапке только действие, которое статус разрешает дальше: черновик → «Mark as sent», открытый → «Mark as paid». Остальное — в ⌘K.                                                                                                                 |

## Телефон

Три колонки не помещаются. Вместо них переключатель **Sheet · Invoice · Design** под шапкой:

- правка на листе работает касанием;
- ⌘K заменяет кнопка с иконкой;
- горизонтальной прокрутки нет.

## Что переиспользовано

Composer — экран уровня `views`: он **собирает** готовые фичи, а не дублирует их.

| Что                                         | Откуда                                                                                 |
| ------------------------------------------- | -------------------------------------------------------------------------------------- |
| Форма, статусы, сохранение, умные умолчания | `features/invoice-editor` (`useInvoiceEditor` получил режим `autosave`)                |
| Секции формы                                | `features/invoice-editor/ui/*-section`                                                 |
| Модель и контролы шаблона                   | `features/template-editor` (провайдер получил `keyboard={false}` и `save({ silent })`) |
| Карта кликов по листу                       | `resolveEditTarget` + `studioTarget` → `views/composer/lib/targets.ts`                 |
| Лист, превью, масштаб                       | `entities/invoice/ui`                                                                  |
| Палитра команд                              | `shared/ui/command-palette`                                                            |

## Проверено

- Правка на месте пишет в ту же форму: сумма строки, итоги и статус пересчитываются, валидация та же.
- Автосохранение создаёт новый счёт один раз и дальше обновляет его. Невалидный счёт не сохраняется, и статус объясняет почему.
- Смена шаблона не теряет правки счёта: форма шаблона пересоздаётся, форма счёта живёт выше.
- Unit-тесты: `views/composer/lib/targets.test.ts`, `shared/ui/command-palette.test.ts`.
